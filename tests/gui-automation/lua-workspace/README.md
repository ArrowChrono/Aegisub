# Lua Workspace S1 source round-trip E2E

This executable exercises the production Lua source utilities and the ASS read/write boundary with the bundled LuaJIT. It is an S1 integration E2E, **not** completion of the Lua Workspace GUI, Run/Debug, or editor integration planned for S2 and later stages.

The harness accepts a repository-relative fixture directory and an explicit artifact directory (which may be absolute). CTest invokes it from the repository root with a finite process timeout. Each executable fixture is evaluated five times against its own hand-written `.expected` business result: original source, formatted source, serialized source, serialized source after a physical ASS save/reopen, and the reopened source formatted again. The last stage verifies that one-line ASS storage remains recoverable as readable statement lines rather than merely executable bytes. JIT compilation is disabled for each execution, and an instruction-count hook bounds interpreted Lua execution. The `validate_only` fixture deliberately contains an error call and an unbounded loop; it is compiled, formatted, and serialized but never executed. Invalid escape and binary-chunk fixtures must fail validation and conversion without changing their source buffers.

Each case retains source variants, actual and expected results, diagnostics where applicable, the input and output ASS files, and `status.txt`. The top-level `manifest.txt` records all cases and remains available after a failure. `classifier` writes several effect lines to ASS, reopens them, runs the repository's `kara-templater.lua` parser with minimal Automation host stubs, and compares its parsed code entries to the C++ classifier. The comment text in lexical fixtures is synthetic tokenizer input, including delimiter-shaped bytes; it is not an issue citation or project documentation.

The `member-access` case additionally checks chained member access, calls, comma-separated arguments, and indexes without extra padding around punctuation. It combines Unicode, long strings, comments, varargs, labels, separated minus tokens, and numeric concatenation (`1 .. 2` and `n .. .5`). The `punctuation` case executes a chained `create_font(...).text_to_shape(...)` call, a long-string index, and consecutive unary minus in original, formatted, and serialized variants. Its independent result checks that compact punctuation does not merge Lua tokens. Targeted spacing checks complement business results; they do not replace semantic round-trip verification.

The `semicolons` case covers statement and table separators, calls and indexes, and Unicode strings/comments containing literal semicolons. Formatting and serialization omit unwanted padding before semicolons and commas and inside call parentheses, while the five execution stages retain the independent result `12|2,3|雪 ; 🌟|文 ; 本`.

The `statement-boundaries` case covers nested control flow, declarations, assignments, calls, a multiline expression and table constructor, and long strings/comments. It requires stable statement lines both before serialization and after the physical ASS is reopened. The separate `historic-single-line` case starts from a valid legacy code line with neither physical newlines nor semicolons and requires the same boundary recovery. Serialization writes only LuaJIT-confirmed separators; formatting keeps expression and table interiors on their statement line. If parsing or equivalence checking cannot establish a safe conversion, the production utility returns the original source with a diagnostic.

The `syntax-boundaries` case combines vararg unpacking, a standalone EmmyLua annotation, uninitialized locals, functions inside table fields, method calls, numeric and generic loops, repeat/until, and goto/labels. Its independent business result survives all five ASS round-trip stages; ordinary-file formatting also preserves the annotation's separate line and the statement after varargs. Statement boundaries are read in one syntax traversal, with LuaJIT remaining the syntax authority and a final bytecode-equivalence check rather than a per-candidate compiler probe.

The generated `scalability` case exercises 512 adjacent ordinary calls, 512 explicit statement semicolons, and 8000 sequential while loops, plus an implicit boundary between a numeric expression and a parenthesized call. It executes the original, formatted, and serialized source against the independent `1025:1` result and retains each stage. The CTest-level 60-second timeout bounds the complete source-roundtrip E2E rather than relying on an unbounded timing retry.

The JIT GUI matrix also invokes the documented current-function form `jit.off(true, true)` and `jit.on(true, true)` during preparation and through a cached function reference at runtime. The language-settings matrix retains manual completion and additionally types a member prefix after the automatic dot-triggered list, then verifies exact insertion; signature requests include whitespace around the member access and before the opening parenthesis. The generated-history matrix includes `long-preview`: input and output have identical truncated previews but different full text, so Context must report a change, and the physically saved ASS must retain the independently expected full strings.

From the repository root, with the configured `build-dir` and `RelWithDebInfo` configuration:

```powershell
cmake --build build-dir --config RelWithDebInfo --target lua-workspace-source-e2e --parallel
ctest --test-dir build-dir -C RelWithDebInfo -R '^lua_workspace_source_roundtrip$' --output-on-failure
```

## S2 editor GUI E2E

`editor-uia.cs` is a separate, bounded Windows UIA driver for the real Lua Workspace frame. It starts `--gui-test host` with an isolated profile, copies `fixtures/editor.ass` and its project-local Automation macro into the artifact directory, opens code through the real Automation menu, edits the Lua source control through guarded input, and inspects the physically saved ASS. The scenario covers local and main undo isolation, multi-code-line decisions, layered close/open cancellation, metadata conflict and invalidation, deletion/undo, and Lua-file persistence and conflict. The read-only Lua-file fault affects only an artifact copy and its original attributes are restored. The manifest records every required step as `passed`, `failed`, or `not-run`; compilation or a partial pass does not establish S2 completion.

From the repository root after building the GUI target:

```powershell
dotnet run tests/gui-automation/lua-workspace/editor-uia.cs -- --exe build-dir/RelWithDebInfo/Aegisub.exe --artifacts build-dir/artifacts/lua-workspace/editor-uia
```

The driver has a 120-second supervising process timeout and per-discovery deadlines. It retains `manifest.json`, `input.ass`, `output.ass` when saved, source buffers, UIA trees, screenshots, clipboard ownership/sequence receipts, and a supervisor cleanup status under the explicit artifact directory. The user clipboard is snapshotted before the worker runs and restored only after the worker and GUI host stop if no external clipboard change intervened. A failed or unrun step must not be inferred successful from a compiled driver.

`applied.ass` is frozen immediately after Apply and main Undo/Redo, before later lifecycle scenarios mutate the test document. Use that artifact, not the final `output.ass`, as the subtitle input for `verify-editor-save.json`; the real headless Automation macro in `fixtures/verify-editor-save.lua` checks the persisted code-once business result `38` and the untouched surrounding lines.

The GUI driver requires Windows, .NET 10, the currently built English application UI, and an unlocked interactive desktop. Do not use the keyboard, mouse, or clipboard concurrently with a run. TaskDialog button aliases cover only the English and Simplified Chinese labels observed during development; another localization fails closed rather than assuming button positions. The file-conflict branches exercise the real choice dialog, including a second external file revision between conflict display and overwrite confirmation. These desktop-global input and clipboard constraints are prerequisites, not a claim of safety under concurrent human or automation activity.

### Workspace layout and editor preferences

Lua Workspace uses a compact, wrapping action row. Its bitmap-only Open, Apply/Save, Format, Reload, Copy, Run, Pause, and Stop controls retain accessible action names and use SVG-backed button assets; the window reuses the Automation icon with an SVG source. The number margin fits the current line-count digits instead of reserving five digits, while the breakpoint click lane and current-execution marker sit to the left of the numbers. The source/debug divider and the editor/output divider are live splitters. Dragging stores `Automation/Lua Workspace/Layout/Source Width Percent` and `Automation/Lua Workspace/Layout/Output Height Percent` in the normal user configuration; resizing to a constrained window does not replace the user's saved proportions. Automation preferences expose `Automation/Lua Workspace/Editor/Wrap`, `Font Face`, and `Font Size`. They update the open source editor and captured execution source immediately and persist across restarts.

A successful switch between a Lua file and a code line, or a successful Reload, clears previous run status/log and debug source/stack/variables; an unsuccessful open preserves the current target and its observation. In the writable source editor, `()`, `[]`, `{}`, single quotes, and double quotes auto-pair as one Undo action outside Lua strings/comments, and typing an existing closer skips it. Language diagnostics occupy one line each; `lowercase-global` includes its exact ranged name. Hover Markdown is displayed as bounded plain text with explicit candidate boundaries rather than raw fences or unlabelled blended definitions.

The independent `editor-uia.cs --scenario workspace-ux` regression uses two normally closed GUI hosts with one isolated profile. It checks wide/narrow toolbar wrapping, equal compact icon widths including Format/Reload, action accessibility, the window icon, genuine single drags of both splitters and saved/restored proportions, live and persisted wrap/font preferences, stale presentation cleanup versus a failed open, and compound pair/skip/Undo input. It has a strict 240-second supervising deadline, preserves screenshots, native control evidence, config and source observations, manifest steps, and clipboard cleanup status. The real font-face rendering, gutter spacing, icon legibility, and empty captured-source area require review of the saved screenshots; configuration values or UI presence alone do not establish those visual facts. Run it from the repository root with a fresh artifact directory:

```powershell
dotnet run tests/gui-automation/lua-workspace/editor-uia.cs -- --scenario workspace-ux --exe build-dir/RelWithDebInfo/Aegisub.exe --artifacts build-dir/artifacts/lua-workspace/editor-workspace-ux
```

## S3 runtime-observation GUI E2E

`runtime-uia.cs` drives the real Automation menu and the Workspace's read-only Context and Generated panes. It copies `fixtures/runtime.ass`, `fixtures/runtime-actions.lua`, `automation/autoload/kara-templater.lua`, and the repository's `automation/include` tree into an isolated artifact directory so the copied template script resolves its normal Lua includes. The independent `fixtures/runtime.expected.json` defines the physical generated ASS events; the driver reads its count and compares each saved line's business fields, rather than hard-coding a count in the UI test. It also covers completion, cancellation, error, rollback, no-output, menu validation, hidden-window isolation, reopening, and one main Undo.

Context labels the observed template **event type** separately from its primary authored **template type**, all authored kinds, phase, and actual applied scope; a shared `syl furi` template may have primary type `syl` while a particular output is applied in `furi` scope. Numeric template debug ID, optional authored template name, owner script, and source line are distinct from the input subtitle's index. Source fragments are enumerated with their own line/kind/text, up to 16 bounded previews; the total, shown, and omitted counts prevent a partial list from masquerading as the complete source. The original input subtitle (`orgline`) and current template line show index, layer, style, text, effect, and millisecond timing side by side with explicit change markers. For syllable contexts, `syl` and `basesyl` expose line-relative timing, duration, inline effect, and karaskel geometry in PlayRes/script coordinates, not screen pixels; missing captures are marked `[not captured]`, while a scope without a syllable is `[not applicable]`. PlayRes comes from the ASS script context. The latest template event is a snapshot, not live debugger-frame values: Context also distinguishes current/last/no pause. Workspace Run/Debug identifies its captured source revision and stale editor state; ordinary Automation-menu runs identify subtitle document generation but explicitly do not claim to capture a saved template revision. The GUI scenario compares these fields to the source ASS and generated-event expectations, checks syllable geometry relationships, and records the complete Context text as an artifact.

Before Workspace is opened, a real dialog-acknowledged macro verifies that a macro run does not create it implicitly. After reopening, four separate real karaoke-template failure scenarios prepare invalid code or expressions and physically save that precise one-field source change, run the production templater, require the corresponding parse/runtime diagnostic and failed observation, verify live ASS rollback with an independent Automation macro, then undo the preparation and physically save the unchanged event baseline. The final one-step main Undo still applies to the original successful template run. An additional lifecycle case queues an OS `WM_CLOSE` while an ordinary Automation-menu macro is active, confirms that the disabled observing Workspace may hide without ending the run, keeps the separate modal progress dialog visible, and cancels through that real control. It does not exercise Workspace Run/Debug or `active_run_request`; those close/Detach guarantees belong to the controls scenario below. The driver finally closes the main window through UIA `WindowPattern.Close` and verifies normal process exit rather than relying on forced cleanup.

The real karaoke templater iterates syllables from index 0 through `kara.n` for the default syllable template. Each of the two karaoke lines therefore produces two line-loop outputs and three syllables (including blank index 0) times two syllable-loop outputs, for 16 generated lines. The explicit `noblank` fixture omits index 0 and expects 12; the `runtime-furi` fixture exercises furigana with an independent 24-line expectation and final `furi` scope. `verify-runtime.ps1` is the separate PowerShell 7 headless E2E for all three variants: it checks every generated event's text, layer, timing, style, and effect, the original event transitions, and each generated-line trace against independent expected data. Run it from the repository root with a fresh artifact directory:

```powershell
pwsh -File tests/gui-automation/lua-workspace/verify-runtime.ps1 -Artifacts build-dir/artifacts/lua-workspace/runtime-headless
```

From the repository root, after building the GUI target:

```powershell
dotnet build tests/gui-automation/lua-workspace/runtime-uia.cs -nologo -v:q
dotnet run tests/gui-automation/lua-workspace/runtime-uia.cs -- --exe build-dir/RelWithDebInfo/Aegisub.exe --artifacts build-dir/artifacts/lua-workspace/runtime-uia
```

This separate 24-step scenario has a finite 1440-second supervising limit: a measured run had passed only 18 steps by 720 seconds, and one template-failure scenario took 115 seconds with three similar scenarios still required. Each operation retains its own bounded deadline and exact assertions; the larger total limit does not turn a failed or incomplete run into a pass. Modal dialog and progress waits begin only after the driver synchronously opens the Automation menu, finds the visible command within its existing eight-second exposure limit, and verifies that the item is enabled and invokable. It then invokes the exact ready item on a worker task before starting the separate eight-second modal wait. This two-phase handoff avoids charging menu discovery and worker scheduling to a modal deadline without an additional outer readiness race or an unbounded wait. It retains the input and saved/restored ASS, source and expected hashes, manifest steps, Context/Generated text, UIA trees, screenshots, and supervisor status. As with S2, a compiled driver or a `not-run` step is not a pass. The run requires the same unlocked Windows/.NET 10 interactive desktop and no concurrent keyboard, mouse, or clipboard activity; only the English application labels and observed system-dialog aliases are covered.

The progress-cancellation fixture's Lua-side interaction window is finite at 30 seconds: a measured run reached its progress pane, but menu discovery plus UIA screenshot capture exhausted the former 10-second window before the driver could click Cancel. Expiry still raises an error, not cancellation. The driver must find a visible enabled exact `Cancel`, click it once through UIA, observe a cancelled outcome, and verify live/physical ASS rollback; supervisor cleanup cannot satisfy this step.

Pass a fresh artifact directory for every GUI run. The supervisor refuses to overwrite an existing directory. Runtime-pane text is read from the strictly identified native Edit control with one bounded, Unicode `WM_GETTEXT` operation, because the UIA TextPattern range can change while a macro updates the pane; an overlong or truncated result is a failure, not a partial observation.

### Generated history and provenance

The Generated tab retains a selectable, invocation-local history of the newest 128 reported output lines under a second 256 KiB retained-string budget. Both limits drop the oldest records, and the pane reports the retained and omitted counts plus `Retained preview bytes: X / 262144`; this byte count covers retained UTF-8 string payloads, not total process memory. Gaps in observed output indices are reported separately rather than fabricated. Each item is captured synchronously with its `generated-line` event, not reconstructed by polling the latest context. It records the output's text, style, layer, effect and millisecond times; the immutable input `orgline` index, text and times captured before user template code can mutate that Lua table; the template debug ID, primary/all authored kinds, source line and fragments; and the applied scope plus syllable, highlight and character indices when available. **Input source line index** names the ASS subtitle being processed; **template source line** names the authored template, so neither falls back to the other. Missing data is displayed as `[not captured]`. For ordinary Automation-menu runs, the saved template source revision is not captured: Workspace editor revisions are explicitly marked unrelated, and changing that editor does not clear the run's history. Workspace Run/Debug instead displays its captured source revision. Generated output is provisional while the macro is running, committed to live ASS only after successful invocation completion, and marked rolled back after cancellation or failure. The historical commit status does not track later Undo, edits or disk saves. Cancelled or failed history is best-effort evidence of *reported* generated events, not a claim to include every provisional `subs.append`: Stop can interrupt between the append and its trace publication.

The independent `generated-history` GUI scenario in `runtime-uia.cs` uses five fresh hosts with normal `WindowPattern.Close` exits. The branches fixture exercises per-character output, two highlights on one syllable, their combined `char multi` path, and a template authored for both `syl` and `furi`; the driver selects non-final records, then edits unrelated Workspace source and requires its history to remain selectable. The mutated-input fixture runs code that changes `orgline.i/text/timing` before generation but requires immutable pre-code input provenance. The long-preview fixture additionally changes only text beyond the preview limit and requires an accurate full-text difference despite identical displayed prefixes. These fixtures compare against hand-authored expected data. The capacity fixture emits 140 short lines and requires precisely #13–#140 retained, #1–#12 omitted, and the independent `R1`–`R140` saved ASS sequence. The cancellation fixture waits for a genuinely observed provisional generated line, cancels through the real progress control, requires rolled-back reported history, and verifies live ASS through a separate Automation macro. Progress discovery checks top-level roots and their direct owned-dialog children with the same exact PID, pane type, native class, title, handle and visibility requirements; it does not walk unrelated editor descendants or extend the modal deadline. Its 660-second supervisor, per-operation deadlines, hashes, UI captures, saved ASS, and manifests make the result reproducible; a timeout, forced cleanup or `not-run` case is not a pass. Run from the repository root, with exclusive access to the unlocked desktop and a fresh artifact directory:

```powershell
dotnet build tests/gui-automation/lua-workspace/runtime-uia.cs -nologo -v:q
dotnet run tests/gui-automation/lua-workspace/runtime-uia.cs -- --scenario generated-history --exe build-dir/RelWithDebInfo/Aegisub.exe --artifacts build-dir/artifacts/lua-workspace/generated-history
```

## S4 Run/Debug GUI E2E

`debug-uia.cs` is a separate, bounded Windows UIA driver. Its synthetic `debug.ass` has two distinct code-once lines, line/syllable/furigana templates with loop 2, and two karaoke dialogues. The driver copies the real karaoke templater and its `automation/include` dependencies beside an isolated ASS artifact. It edits the first code-once buffer to a multiline function without Apply, starts an actual Debug invocation with a UI breakpoint, checks a paused immutable execution-source control against that buffer, edits the buffer again and requires a stale-revision indicator while the paused source stays unchanged, then stops and checks rollback. The later Run path expects 24 generated events from the independently authored `debug.expected.json`, compares every event's text/layer/timing/style and the unchanged code/template lines, saves the ASS physically, undoes one main commit, and exercises Detach as a separate normal-commit path.

The basic scenario additionally runs an independent managed macro to compare every live ASS event after Stop, then discards only its unsaved Workspace buffer and closes the main window normally. Its 11 steps cover the captured karaoke revision and generated-output path. It explicitly enables `Pause on entry` before its entry-dependent assertions; entry pause is no longer the default Debug behavior. The full S4 matrix also requires the separate launch, controls, files, dap, and jit scenarios, the native virtual-source integration target, and S2/S3 regressions on the same executable. Every manifest explicitly reports only its own scenario; a passing group does not establish full-stage completion. Each mode returns nonzero for failed or unrun steps, retaining the manifest, inputs, source hashes, bounded same-process native HWND inventories, real screenshots, evidence timings, exact menu-invocation observations, and supervisor cleanup status. Evidence capture does not recursively enumerate the variable tree through UIA; semantic assertions still address the exact stack, tree, location, details, source, menu, and ASS state separately.

The `--scenario launch` branch is the bounded default-launch and Debug UX acceptance. It keeps `Pause on entry` off, edits a karaoke code chunk to contain a captured upvalue, places its line-3 breakpoint with a guarded physical click in the left glyph margin, and requires the first observed pause to be `breakpoint #1` rather than an entry pause. At that pause it checks the visible `Paused at ... [editable source]` mapping, automatic Stack-and-Variables navigation, initially expanded Locals/Upvalues, initially collapsed large scopes, nested tree navigation, and exact selected-variable details. It retains screenshots with the breakpoint and current-line arrow in separate margins to the left of the line number for visual review, then clears the editor breakpoint and retains another exact paused screenshot of the arrow. The running session intentionally keeps its frozen breakpoint set: Continue must reach `breakpoint #2` with the next input value, after which Detach lets the invocation complete and the retained location/details must say that the last-pause snapshot is not current or live. A second Debug with no breakpoints must complete naturally without exposing any pause; its bounded waiter issues no resume, step, detach, or stop command, so any unexpected pause prevents natural return and fails the scenario. Finally, enabling `Pause on entry` explicitly must restore entry `#1`; Stop, two independent live-ASS baseline verifications, normal GUI exit, and clipboard restoration remain required. These seven steps cover both the default path and the opt-in compatibility path without weakening the older entry/step scenarios.

The `--scenario controls` branch uses the same supervisor and a separate fresh artifact directory. It explicitly enables `Pause on entry`, then opens saved ordinary Lua files through the real picker: `debug-steps.lua` requires exact entry/step reasons, increasing pause sequences, source lines 10/6/2/7/11, and stack-depth transitions for Step In/Out/Over. It then saves the one-field `step:8` ASS result and requires one main Undo to restore all original events. `debug-loop.lua` makes a provisional live ASS edit before a bounded CPU loop and emits a unique progress-task marker; the driver exercises Pause/Continue/Stop, requires a project-local macro to compare every live dialogue field against independent seed expectations, checks the physical ASS, and uses one main Undo to prove no cancelled undo entry survived. Further controls steps queue OS close to a verified Workspace HWND and preserve both close decisions. Stop-then-close still cancels, rolls back, and hides only after the invocation ends. Detach keeps the Workspace visible as the last usable control surface while the main subtitle frame remains disabled: a non-debug Run of nonterminating `debug-infinite-loop.lua` must expose Detach, then stop through the visible Stop button and roll back; a separate Debug of the bounded loop must complete naturally, commit its one-field change, save, and undo. Its 15 steps run under the driver's finite 240-second supervisor budget, require normal shutdown, and supply the live rollback and close-lifecycle evidence that the basic branch alone lacks; it does not stand in for DAP or JIT acceptance.

The R1 entry scenarios (`entry-late`, `entry-zh`, `entry-once`, `entry-missing`, `entry-ambiguous`) use `workspace-entry.ass` and reproducibly insert 51 non-template dialogue events ahead of a later template. The ordinary Automation menu must still disable the templater through its fast validation and keep a separate validation-rejected macro disabled; Workspace Run instead uses the built-in templater's nontranslated execution ID and scans the complete subtitle document. English and Simplified Chinese runs require the independently expected generated `R1-LATER1-LATE` event in the physically saved ASS. The Chinese scenario compiles the repository PO with the CMake-configured gettext tool into the build output locale directory and retains a copy of that catalog in its artifacts, so a build with `WITH_TRANSLATION=OFF` is still testable without changing its CMake cache. The code-once-only variant has no template line, requires the real run log's code execution marker, and leaves physical subtitles unchanged. Missing or duplicate execution IDs must report an explicit selection error without committing. Each scenario retains its prepared ASS, menu-state records, run log, UI evidence, and manifest. The `--scenario files` branch covers E18 through real file and macro-selection dialogs. Opening or saving a no-entry file must not execute its top-level code; an attempted Run loads it exactly once, reports the missing macro, and disables that revision until editing or Reload. Recovery must execute the newly registered macro. A read-only UTF-8 BOM file must retain its original bytes after failed Save, keep the edited buffer, and leave live ASS unchanged; making the artifact writable then permits the exact edited macro to run. A managed two-macro file exercises exact selection and Save/Reload from Beta to Gamma, including removal of the old menu entry, complete saved ASS comparison, and Undo. All 15 steps, including normal shutdown, are required.

The R3 `--scenario preparation` branch covers the cancellable preparation lifecycle before a macro body starts. Separate ordinary Lua files loop in top-level code, an `include()` body, and a macro validation callback. Each must expose an exact `Preparing...` status and a visible enabled Workspace Stop while Run, Debug, Open File, and Reload are disabled and the main frame is locked. Stop must return through the UI action rather than supervisor cleanup, report a cancelled terminal state, release the main frame and local session, preserve the physical and independently verified live ASS baseline, and permit the same artifact file to be replaced on disk, explicitly reloaded through Workspace, and run successfully. Another top-level fixture attempts `debug.sethook`, requires an explicit rejection of cancellation-hook replacement, then enters a Lua loop that must still stop through the visible control. Additional paths require cleanup after a missing include, a validation rejection, a distinct validation runtime error, and cancelling the real two-macro selection dialog; the latter is followed by a successful selection and run. R3 verifies cooperative cancellation of ordinary Lua execution, not forced termination of arbitrary native calls or LuaJIT `__gc` finalizers (LuaJIT disables debug hooks during finalizers). Workspace avoids an extra forced full GC at the end of its guarded calls, but script-triggered GC and state destruction still obey that VM limitation. The driver retains finite per-operation deadlines and a 300-second preparation supervisor, whose forced process termination is failure cleanup only.

The `--scenario dap` branch uses a real loopback TCP DAP client and an isolated test-token profile. Its redacted NDJSON transcripts retain requests and responses. It checks remote ownership rejection, local ownership rejection of attach/continue/breakpoint requests, disconnect/terminate isolation, the real Ctrl+S Apply boundary, and live ASS rollback with the listener enabled. Requests have bounded framing and total deadlines; malformed protocol data is not treated as successful disconnect. It also posts native commands using runtime-observed menu and control IDs to test subtitle/open and second-Run rejection at their production entry points. Both must report the full rejection message while preserving the paused source, stack, and ASS; disabled controls alone do not pass. This is controlled command delivery, not a claim that a user can click a disabled control. All 19 steps are required.

The `--scenario jit` branch covers explicit engine on/off crossed with completed/failed/cancelled outcomes. The ordinarily loaded managed script first proves it can retain a real hot-loop trace. A Workspace candidate reload instead keeps top-level Lua interpreted and cancellable: it cannot truthfully retain that prewarm trace, even when the script requests `jit.on()`. The separate preparation scenario stops a top-level loop after that request. Each JIT invocation requires no retained preparation trace, a disabled engine and no trace during Macro Run, and restoration of the script-requested on/off engine mode in the same managed Lua state through an ordinary Automation-menu verifier. Cancellation still requires a post-write handshake, exact-source manual Pause in the hot loop, Continue, Stop, and an independent live ASS baseline check. All six cases and normal shutdown form a 28-step matrix with source hashes, state observations, and ASS evidence. The additional initial prewarm and six full Run/verify/ASS paths use a finite 360-second supervisor budget; each operation-specific deadline remains bounded and unchanged.

## S5 coding-line edit box E2E (E17)

The main subtitle edit box remains a single physical ASS line, not a second multiline Workspace buffer. A comment whose Effect begins with the word `code` uses Lua highlighting when STC is enabled. It excludes ASS spelling, tag manipulation, character markers, and color swatches. Template lines and non-comment dialogue lines retain their normal ASS behavior. Code-line edit box and Automation menu both use the single `automation/lua/open-current-line` command. Its default `Shift+Enter` binding lives in the configurable `Lua Code Edit Box` hotkey context; the duplicate edit-box button and hard-coded shortcut were removed. An existing custom binding is preserved during migration, and ordinary subtitle `Shift+Enter` still inserts `\N`. The existing `Subtitle/Use STC=false` preference keeps the plain editor, with the safe paste and Workspace entry behavior but without Lua highlighting.

Single-line code paste is literal. Multiline paste serializes the complete replacement candidate through the existing Lua source serializer before making any edit. An invalid candidate produces a diagnostic directing the user to Workspace and leaves the source unchanged. Incomplete multiline editing therefore belongs in Workspace rather than being silently flattened or translated to ASS escapes. Code-mode character input also blocks raw newline characters that reach the control after hotkey handling; E17 checks Ctrl+Enter against an exact unchanged source in both modes.

`coding-editbox-uia.cs` runs the E17 scenario separately for STC and plain controls. It uses five events with distinct timing, layer, actor, margins, effect, and comment state. Its complex paste contains Unicode, a multiline long string, a comment, and a loop. It saves the physical ASS, rejects an invalid multiline replacement atomically, tests literal paste and Undo, opens Workspace through a custom `F6` code-only hotkey and the same Automation command, and verifies that migrating the profile does not add an unwanted `Shift+Enter` binding. The custom profile deliberately omits `Ctrl+V` to exercise the controls' native paste routes while retaining document-level `Ctrl+Z`/`Ctrl+Y` for exact Undo/Redo assertions. The obsolete edit-box button must be absent. STC-specific steps exercise Tab, brace input without ASS auto-close, disabled ASS block movement, and context-menu mode separation; ordinary subtitle editing must still move an ASS block and convert multiline paste and `Shift+Enter` to exact literal `\N` text. Comment and Effect edits must reclassify an unchanged source immediately.

The final save compares all five events' physical fields against independent fixture expectations. A separate bounded headless invocation executes the saved CodeA Lua and requires the result `漢字\nsecond:10`, verifies every remaining event, and confirms that verification itself did not mutate the saved events. Screenshots are retained for parent review of Lua/ASS highlighting; compilation and screenshots alone do not establish E17 completion.

Ordinary-text Undo retains each control's existing grouping contract. STC starts a new main undo group on its native action marker; the plain editor coalesces consecutive, unsaved text edits. E17 keeps the consecutive paste/Shift+Enter/Undo scenario in both modes, checks the exact mode-specific snapshot, redoes the complete text, and undoes it again. It records these values in `ordinary-undo.json` rather than assuming STC granularity for the plain editor. Navigation input uses standard extended-key flags, empty Effect fields are checked after their native placeholder clears on focus, and Effect changes use real keyboard input rather than UIA value assignment that can bypass combo-box edit notifications.
